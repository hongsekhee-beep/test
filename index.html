작업 단계 안내
이 문서는 웹사이트 제작을 위한 프롬프트이며, 가상 핸드폰 웹사이트 자체의 실행 코드가 아닙니다. 별도 요청 전까지 실제 프로젝트 코드는 작성하지 않습니다.

1. 프로젝트 목표

참고 사이트 https://wonbin-phone.pages.dev/ 의 핵심 콘셉트를 참고해, 사용자가 실제 아이폰을 사용하는 것처럼 느낄 수 있는 박성호 중심의 iPhone 17 Pro 가상 핸드폰 웹사이트를 제작한다.

이 프로젝트는 단순한 아이폰 모형이나 정적인 화면 모음이 아니라, 잠금 화면부터 홈 화면, 제어 센터, 알림 센터, 여러 기본 앱까지 실제로 조작할 수 있는 웹 기반 인터랙티브 시뮬레이터다.

중요: 현재 단계에서는 코드를 작성하지 않는다. 먼저 전체 구조, 화면 구성, 데이터 모델, 보안, 저장 방식, 배포 방법을 설계하고 구현 계획을 제시한다. 실제 코드 작성은 별도로 요청받은 뒤 진행한다.

2. 기본 사양

  • 기기: iPhone 17 Pro
  • 프레임: 실버 계열
  • 중심 인물: 박성호
  • 기본 언어: 한국어
  • 화면: 실제 iPhone 화면 비율을 유지한 세로형
  • 지원 환경: 모바일, 태블릿, PC
  • PC에서는 핸드폰 화면을 더 크게 표시하되 화면 비율을 유지한다.
  • iOS 특유의 글꼴, 여백, 아이콘, 둥근 모서리, 다이내믹 아일랜드, 상태 표시줄, 홈 인디케이터, 스크롤, 모달, 화면 전환을 최대한 정밀하게 재현한다.
  • 터치와 마우스 입력을 모두 지원한다.
  • 실제 iOS 기기나 운영체제에 접근하는 것이 아닌 웹 기반 시뮬레이터임을 전제로 한다.
  • 소리와 진동은 구현하지 않는다. 시각적 애니메이션만 사용한다.
  • 웹사이트 접속 시 별도의 소개 화면 없이 잠금 화면을 바로 표시한다.

3. 잠금 화면과 잠금 해제

잠금 화면

  • 실시간 시계와 날짜를 방문자의 기기 현지 시간에 맞춰 표시한다.
  • Wi-Fi, 이동통신 신호, 배터리 상태를 iOS와 유사하게 표현한다.
  • 배터리 표시 수준은 관리자가 별도로 변경하지 않는 한 고정된 값으로 표시한다.
  • 잠금 화면 배경은 기본 제공 배경과 관리자 업로드 이미지 중 선택할 수 있다.
  • 잠금 화면과 홈 화면 배경은 서로 독립적으로 설정할 수 있다.
  • 잠금 화면 위젯은 관리자가 종류, 위치, 표시 내용 등을 설정할 수 있다.
  • 알림은 자동으로 표시하거나 관리자가 직접 추가·수정·삭제할 수 있다.
  • 알림을 누르면 해당 앱 또는 관련 콘텐츠로 이동한다.

잠금 해제

  • 위로 스와이프하면 4자리 비밀번호 입력 화면을 표시한다.
  • 고정 비밀번호는 0810이다.
  • 비밀번호가 일치하면 자연스러운 iOS 스타일 애니메이션으로 잠금 해제한다.
  • 틀린 비밀번호는 횟수 제한 없이 다시 입력할 수 있다.
  • 수동 잠금과 일정 시간 동안 조작하지 않았을 때의 자동 잠금을 지원한다.
  • 자동 잠금 대기 시간은 관리자 설정에서 변경할 수 있다.
  • 다시 잠금을 해제할 때마다 비밀번호를 요구한다.
  • 가상 핸드폰 비밀번호와 관리자 로그인 비밀번호는 완전히 별개로 취급한다.

4. 홈 화면과 앱 아이콘

  • 실제 iOS와 유사한 기본 앱 배열 및 아이콘을 제공한다.
  • 앱 아이콘은 가능한 범위에서 실제 앱을 연상시키는 공식 스타일을 사용한다.
  • 관리자는 아이콘 위치와 순서, 홈 화면 페이지, 위젯 종류·크기·위치·내용을 편집할 수 있다.
  • 아이콘 이동은 드래그 방식으로 지원한다.
  • 독(Dock)은 기본 앱 4개를 고정 배치하며 방문자에게는 편집 기능을 제공하지 않는다.
  • 지원 앱 목록은 고정한다. 관리자는 앱을 추가하거나 삭제할 수 없지만 아이콘 위치와 순서는 바꿀 수 있다.
  • 홈 화면 배경은 기본 배경과 관리자 업로드 이미지 중 선택한다.
  • 앱을 누르면 아이콘이 확대되며 앱 화면으로 전환되고, 닫으면 아이콘으로 돌아가는 애니메이션을 제공한다.
  • 앱 전환 제스처로 최근 앱 카드 화면을 표시한다.
  • 최근 앱 카드를 선택하면 해당 앱으로 이동하고, 카드를 위로 밀면 가상 실행 상태를 종료한다.
  • 앱 사이를 이동할 때 대화 위치나 열어 둔 콘텐츠 등 가능한 화면 상태를 유지한다.

기능이 실제 외부 서비스나 기기 기능에 의존하는 경우에는 가상 환경 안에서 합리적으로 시뮬레이션한다.

사진

  • 실제 iOS 사진 앱을 참고한 앨범 목록, 사진 그리드, 전체 화면 보기 등을 제공한다.
  • 관리자는 사진과 앨범을 업로드·수정·삭제하고 표시 순서를 바꿀 수 있다.
  • 방문자는 사진을 열고 확대해서 감상할 수 있다.
  • 업로드 이미지는 자동 최적화하며, 필요한 경우 원본 보존을 선택할 수 있다.

메시지

  • 실제 iOS 메시지 앱과 유사한 대화 목록과 대화방 화면을 제공한다.
  • 대화 상대별 이름, 프로필 이미지, 메시지 내용, 날짜, 시간, 읽음 상태, 사진 메시지 등을 표시한다.
  • 읽지 않은 메시지 수와 앱 아이콘 배지를 지원한다.
  • 관리자는 대화와 메시지를 추가·수정·삭제하고 순서를 관리할 수 있다.
  • 방문자는 대화를 열어 읽을 수 있지만 실제 외부로 메시지를 전송할 수 없다.

카카오톡

  • 실제 iOS 카카오톡 인터페이스를 최대한 가깝게 재현한다.
  • 대화 목록, 프로필, 대화방, 메시지, 사진 메시지, 날짜와 시간, 읽지 않은 메시지 수 등을 지원한다.
  • 관리자는 대화와 메시지 및 표시 순서를 편집할 수 있다.
  • 실제 카카오톡 계정이나 서버에 연결하지 않는다.

전화

  • 즐겨찾기, 최근 통화, 연락처, 키패드 화면을 제공한다.
  • 발신 버튼을 누르면 가상 발신 화면으로 전환한다.
  • 통화 종료 화면, 부재중 전화, 통화 시간, 통화 기록 등을 시뮬레이션한다.
  • 실제 전화 연결, 음성 통화, 이동통신 기능은 사용하지 않는다.
  • 관리자는 통화 기록과 상태를 추가·수정·삭제할 수 있다.

연락처

  • 실제 iOS 연락처 앱을 참고한 목록, 검색, 상세 프로필, 즐겨찾기를 제공한다.
  • 연락처마다 이름, 사진, 전화번호 등 기본 정보를 관리한다.
  • 전화 버튼을 누르면 가상 전화 앱의 발신 화면으로 이동한다.
  • 메시지 버튼을 누르면 연결 가능한 해당 가상 대화 화면으로 이동한다.
  • 관리자는 연락처를 추가·수정·삭제하고 순서를 관리할 수 있다.
  • 다른 앱의 인물 정보와 자동 동기화하지 않는다. 연락처, 카카오톡, 메시지, 인스타그램 등은 각 앱에서 이름과 프로필 이미지를 독립적으로 관리한다.

인스타그램

  • 실제 iOS 인스타그램을 참고한 프로필, 피드, 게시물 상세 화면, 스토리를 제공한다.
  • 관리자는 프로필 정보, 사진, 게시물, 설명, 스토리를 관리한다.
  • 좋아요와 댓글 수는 가상 콘텐츠에 설정된 값으로 표시할 수 있다.
  • 실제 인스타그램 계정이나 API에 연결하지 않는다.

캘린더

  • 월별·주별 보기와 날짜 선택 기능을 제공한다.
  • 일정에는 제목, 날짜, 시간, 장소, 메모, 색상을 설정할 수 있다.
  • 관리자는 일정을 추가·수정·삭제하고 순서를 관리할 수 있다.

메모

  • 실제 iOS 메모 앱과 유사한 목록 및 상세 화면을 제공한다.
  • 검색, 폴더, 서식 있는 텍스트, 체크리스트 등을 지원한다.
  • 메모의 작성 날짜, 폴더, 내용을 관리할 수 있다.
  • 관리자는 메모를 추가·수정·삭제하고 순서를 관리할 수 있다.

Safari

  • Safari와 유사한 주소 입력 및 브라우저 인터페이스를 제공한다.
  • 실제 웹사이트로 이동할 수 있는 기능을 구현할 경우, 외부 링크임을 구분하고 안전하게 처리한다.
  • 브라우저 화면의 모든 동작을 실제 iOS Safari와 동일하다고 가장하지 않는다.
  • 외부 사이트에서 웹사이트에 허용되지 않는 임의의 콘텐츠를 삽입하거나 실행하지 않는다.

설정

  • 배경화면, 밝기, 다크 모드, 일부 가상 시스템 설정을 제공한다.
  • 실제 기기의 Wi-Fi, 블루투스, 배터리, 개인정보 설정을 변경하지 않는다.
  • 관리자가 설정한 시스템 상태와 모순되지 않게 동작한다.

시계

  • 실제 기기의 현지 시간을 표시한다.
  • 시계, 타이머, 스톱워치 등 구현 가능한 기능을 가상으로 제공한다.
  • 실제 알람이나 운영체제 알림을 보장하지 않는다.

날씨

  • 날씨 앱은 가상 UI로 구현한다.
  • 외부 날씨 API 연동은 선택적으로 설계하고, API 키를 클라이언트 코드에 노출하지 않는다.
  • 외부 API를 연결하지 않는 경우 관리자가 지역, 기온, 날씨 상태, 아이콘 등을 직접 입력해 관리할 수 있도록 한다.
  • 실제 날씨 정보와 관리자가 입력한 가상 날씨 정보를 혼동하지 않도록 데이터 출처를 명확히 구분한다.

6. 제어 센터와 알림 센터

제어 센터

  • 화면 오른쪽 위에서 아래로 스와이프하면 열린다.
  • 실제 iOS 제어 센터를 참고한 시각적 재현을 제공한다.
  • 밝기, 음량 슬라이더 및 주요 버튼을 작동시킨다.
  • 손전등과 다크 모드 버튼은 가상 화면 상태를 변경한다.
  • 밝기 조절은 가상 화면의 시각적 밝기에만 영향을 준다.
  • 실제 기기의 하드웨어 기능은 제어하지 않는다.

알림 센터

  • 실제 iOS와 유사한 열기·닫기 동작과 레이아웃을 제공한다.
  • 잠금 화면 알림과 일관된 알림 데이터를 사용한다.
  • 알림을 누르면 해당 앱의 관련 화면이나 콘텐츠로 이동한다.
  • 알림은 관리자 페이지에서 추가·수정·삭제할 수 있다.

7. 콘텐츠와 인물 정보 원칙

  • 중심 인물은 박성호다.
  • 앱별 콘텐츠의 분위기와 성격은 관리자가 자유롭게 결정한다.
  • 실제 인물의 비공개 데이터나 개인 계정에 자동으로 접근하지 않는다.
  • 콘텐츠는 관리자가 직접 작성하거나 업로드한다.
  • 최초 화면에는 각 앱의 기능을 확인할 수 있는 소량의 예시 콘텐츠를 제공한다.
  • 예시 콘텐츠는 실제 비공개 대화나 실제 기록으로 오인되지 않도록 구성한다.
  • 관리자는 모든 예시를 수정하거나 삭제할 수 있다.
  • 앱마다 인물 이름과 프로필 사진을 독립적으로 설정한다.
  • 방문자의 조작이 관리자 콘텐츠를 변경하지 않도록 한다.

8. 관리자 페이지

관리자 페이지는 /admin 경로에 별도로 제공한다.

로그인 및 보안

  • 관리자 로그인은 비밀번호 방식으로 구현한다.
  • 관리자 비밀번호는 환경 변수 또는 서버 측 비밀 저장소에 보관한다.
  • 비밀번호를 프런트엔드 코드, 공개 설정 파일, 클라이언트 번들에 포함하지 않는다.
  • 서버에서 비밀번호를 검증한다.
  • 로그인 세션을 안전하게 관리하고 관리자 전용 권한을 적용한다.
  • 모든 데이터 변경 작업은 서버에서 권한을 확인한 후 실행한다.
  • 비인증 사용자는 관리자 API를 통해 데이터를 변경할 수 없어야 한다.
  • 데이터베이스와 이미지 저장소에 방문자가 직접 쓰기 작업을 할 수 없도록 권한을 설정한다.
  • 인증 실패, 세션 만료, 권한 없음 등의 상황을 안전하게 처리한다.
  • 가상 핸드폰의 0810 비밀번호를 관리자 인증에 재사용하지 않는다.

  • 앱별 콘텐츠 편집기
  • 실시간 가상 핸드폰 미리보기
  • 저장되지 않은 변경사항 표시
  • 저장 버튼과 취소 버튼

미리보기에는 편집 중인 초안이 즉시 반영되지만, 일반 방문자에게는 저장 완료된 데이터만 공개한다.

저장 버튼을 누르면 변경사항을 서버에 저장한다. 취소 버튼을 누르면 저장되지 않은 변경사항을 폐기하고 마지막 저장 상태로 되돌린다. 자동 저장은 사용하지 않는다.

  • 잠금 화면 위젯 및 홈 화면 위젯
  • 앱 아이콘 배열과 페이지
  • 알림

  • 메시지와 카카오톡 대화
  • 전화 기록

  • 캘린더 일정
  • 메모
  • 가상 시스템 설정 및 날씨 데이터

콘텐츠 입력

  • 파일 업로드
  • 텍스트 직접 입력
  • 드래그 방식 순서 변경

파일을 업로드할 때 미리보기와 업로드 상태를 표시하고, 실패 시 재시도할 수 있도록 한다.

9. 데이터 저장과 이미지 처리

  • 데이터는 온라인 데이터베이스에 저장한다.
  • 이미지와 사진은 별도의 온라인 이미지 저장소에 저장한다.
  • 저장된 데이터는 여러 기기에서 동일하게 조회할 수 있어야 한다.
  • 관리자 변경사항은 저장 버튼을 눌렀을 때만 공개 데이터에 반영한다.
  • 데이터베이스 기록과 이미지 저장소의 참조가 일관되도록 처리한다.
  • 사용하지 않는 이미지의 정리 정책을 마련한다.
  • 이미지 업로드 시 웹 표시용 이미지 최적화를 수행한다.
  • 선택적으로 원본 이미지도 보존한다.
  • 파일 유형과 크기를 서버에서 검증하고 업로드 오류를 처리한다.
  • 무료 서비스의 저장 용량, 대역폭, 요청 수, 파일 크기 제한을 고려한다.

10. 백업과 버전 관리

  • 예약된 자동 백업
  • 관리자 수동 백업
  • 변경 버전 기록
  • 선택한 버전 복원
  • 복원 전 확인 절차

백업에는 데이터베이스 콘텐츠와 이미지 참조 정보가 함께 포함되어야 한다. 이미지 자체를 백업할 수 없는 환경이라면 복원 가능 범위를 명확히 문서화한다.

백업 주기와 보관 기간은 선택한 서비스의 무료 요금제 제한을 고려해 설정한다. 복원 중 오류가 발생하더라도 현재 데이터를 불완전하게 덮어쓰지 않도록 안전하게 처리한다.

11. 방문자 상호작용 저장 정책

  • 방문자에게 별도의 회원가입이나 로그인을 요구하지 않는다.
  • 방문자의 좋아요 표시, 체크리스트 상태 등 가상 상호작용은 현재 방문 중에만 유지한다.
  • 새로고침하거나 방문을 종료하면 방문자 상호작용 상태를 초기화한다.
  • 방문자의 상태는 관리자 데이터베이스에 영구 저장하지 않는다.
  • 방문자의 상호작용이 관리자 콘텐츠를 수정하거나 덮어쓰지 못하도록 한다.

12. 반응형 디자인과 접근성

  • 모바일과 태블릿에서는 기기 프레임이 화면을 과도하게 차지하지 않도록 한다.
  • PC에서는 충분히 큰 기기 화면을 표시하되 세로 비율을 유지한다.
  • 작은 화면에서도 주요 조작이 가능하도록 한다.
  • 스와이프뿐 아니라 필요한 곳에는 클릭·탭 대체 조작을 제공한다.
  • 모달, 키패드, 드롭다운은 화면 밖으로 잘리지 않도록 한다.
  • 키보드 포커스와 기본적인 접근성을 고려한다.
  • 이미지가 로딩되지 않거나 데이터가 없을 때 깨진 화면 대신 적절한 빈 상태를 표시한다.

13. 기술 스택 및 무료 배포

  • 무료 호스팅과 무료 이용 한도가 있는 온라인 데이터베이스 및 이미지 저장소 조합을 우선한다.
  • 특정 서비스 하나를 무조건 고정하지 말고, 구현 시점에 실제 무료 요금제와 기능을 확인한 뒤 적합한 조합을 선택한다.
  • 프런트엔드와 서버 측 인증·데이터 접근 권한을 분리한다.
  • 비밀 키는 환경 변수 또는 서버 측 비밀 저장소를 사용한다.
  • 실제 사용 중인 서비스의 무료 이용 한도, 이미지 저장 제한, 데이터베이스 제한을 문서화한다.
  • 무료 한도 초과 시 데이터 손실이나 무단 변경이 발생하지 않도록 오류 상태를 처리한다.
  • 관리자 설정 및 콘텐츠가 배포 후에도 유지되도록 한다.
  • 배포 방법과 환경 변수 설정 방법을 별도로 문서화한다.

14. 구현 완료 기준

  1. 사이트 접속 시 잠금 화면이 먼저 표시된다.
  2. 비밀번호 0810으로 잠금 해제가 가능하다.
  3. 틀린 비밀번호 입력 횟수에 제한이 없다.
  4. 홈 화면, 제어 센터, 알림 센터의 주요 동작이 작동한다.
  5. 12개 앱이 열리고 각 앱의 핵심 화면이 구현되어 있다.
  6. 연락처의 전화·메시지 버튼이 해당 가상 앱으로 이동한다.
  7. 관리자가 모든 지정 콘텐츠를 편집할 수 있다.
  8. 저장 전 변경사항은 방문자에게 공개되지 않는다.
  9. 저장된 데이터와 이미지가 새로고침 및 다른 기기에서도 유지된다.

10. 방문자는 관리자 권한 없이 데이터를 변경할 수 없다.

11. 자동 백업과 수동 백업 및 버전 복원 절차가 제공된다.

12. 모바일과 PC에서 레이아웃이 정상적으로 작동한다.

13. 실제 전화, 메시지, 외부 SNS 계정, 하드웨어 기능과 연결된다고 오해하게 만들지 않는다.

14. 무료 배포 서비스의 한계와 설정 방법이 문서화되어 있다.

15. 작업 진행 순서

  1. 전체 아키텍처와 데이터 모델 설계
  2. 무료 서비스 조합과 보안 방식 확정
  3. 잠금 화면 및 홈 화면 구현 계획
  4. 공통 iOS UI 컴포넌트 설계
  5. 각 앱의 화면 및 상호작용 설계
  6. 관리자 대시보드 및 앱별 편집기 설계
  7. 서버 인증, 데이터베이스, 이미지 저장소 연결 계획
  8. 백업 및 복원 설계
  9. 반응형 화면과 접근성 검토

10. 테스트 항목과 배포 절차 작성

각 단계에서 실제 구현 가능성, 보안, 무료 요금제 한계, 데이터 일관성을 점검한다. 확정되지 않은 사항은 임의로 사실처럼 단정하지 말고 합리적인 기본값을 명시한다. 사용자가 코드 작성을 요청하기 전에는 코드를 작성하지 않는다.
